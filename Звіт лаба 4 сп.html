Мета роботи

Опанувати методи профілювання програм у середовищі Linux (perf, FlameGraph), проаналізувати ефективність виконання коду, споживання енергії та реалізувати низькорівневу оптимізацію з використанням векторних інструкцій (AVX2).

1. Аналіз неоптимізованої програми (primes_naive)

Програма реалізує наївний алгоритм пошуку простих чисел з часовою складністю O(N2)O(N^2)O(N2) (перевірка дільників до N/2N/2N/2). Вхідні дані: N=300,000N = 300,000N=300,000.

1.1. FlameGraph виконання (Крок 1)

Аналіз:
Отриманий FlameGraph має чітко виражену структуру “вежі”.

  • Hotspot: Функція isPrime займає 99% ширини графіка, що свідчить про те, що майже весь час CPU витрачається саме в ній.
  • Стек: Видно, що функція main викликає isPrime. Відсутність вбудовування (inlining) при компіляції з -O0 створює значні накладні витрати на виклик функції.

1.2. Статистика виконання (Крок 2)

Основні показники (time & perf):

  • Час виконання: 8.51 с
  • User Time: 8.51 с (Програма є 100% CPU-bound).
  • System Time: 0.00 с (Відсутність системних викликів).
  • Кількість інструкцій: 26.1 млрд.
  • IPC (Instructions Per Cycle): 1.40. Це середній показник, що вказує на те, що процесор часто очікує завершення повільних операцій (наприклад, ділення idiv).
  • L1 Cache: Висока інтенсивність завантажень (9.3 млрд), що підтверджує активне використання стеку замість регістрів.

3. Оптимізація та Порівняльний аналіз (Крок 4)

3.1. Суть оптимізації

Було застосовано два рівні оптимізації:

  1. Алгоритмічна: Зменшення простору пошуку дільників з N/2N/2N/2 до N\sqrt{N}N​.
  2. Апаратна (AVX2): Використання SIMD-інструкцій для паралельної перевірки 8 дільників за одну операцію.

3.2. Порівняння Асемблерного коду (Крок 4.1)

  • До оптимізації (-O0): Використовується інструкція idivq (цілочисельне ділення), яка є скалярною (обробляє одне число за раз) і має високу латентність (десятки тактів). Активно використовується стек для передачі змінних.
  • Після оптимізації (AVX): Код використовує 256-бітні регістри %ymm. Ключові інструкції:
    • vcvtdq2ps — конвертація цілих чисел у float (пакетно).
    • vdivps — векторне ділення (8 чисел одночасно).
    • vpmovmskb — створення маски результатів для швидкої перевірки.

3.3. Зміни на FlameGraph (Крок 4.3)

FlameGraph для оптимізованої версії (побудований на збільшеному навантаженні N=10,000,000N=10,000,000N=10,000,000) показує зміну профілю виконання. Хоча функція isPrime_AVX все ще присутня, щільність коду всередині неї змінилася: замість довгих затримок на діленні, виконуються швидкі векторні операції.

Загальний висновок

Поєднання алгоритмічної оптимізації та використання SIMD-інструкцій (AVX2) дозволило скоротити час виконання задачі у 560 разів.
Експеримент підтвердив стратегію “Race-to-Sleep”: найбільш енергоефективним підходом є максимальне використання ресурсів процесора (навіть зі збільшенням миттєвої потужності до 7.8 Вт) для якнайшвидшого виконання задачі та переходу в режим сну.

Додаток: Журнал використаних команд

Крок 1: Побудова FlameGraph

  • g++ -O0 -g primes.cpp -o primes_naive — компіляція без оптимізації;
  • sudo perf record -F 99 -g ./primes_naive 300000 — запис профілю виконання;
  • sudo perf script > out.perf — конвертація логу;
  • FlameGraph/stackcollapse-perf.pl out.perf > out.folded — згортання стеків;
  • FlameGraph/flamegraph.pl out.folded > primes_naive.svg — генерація SVG.

Крок 2: Збір статистики виконання

  • /usr/bin/time --verbose ./primes_naive 300000 — вимір часу та пам’яті;
  • sudo perf stat -d ./primes_naive 300000 — збір детальної апаратної статистики;
  • sudo perf report — перегляд інтерактивного звіту.

Крок 3: Вимірювання енерговитрат

  • sudo perf list | grep 'power/energy' — перевірка подій RAPL;
  • sudo perf stat -a -e 'power/energy-pkg/' sleep 10 — замір базового споживання (Idle);
  • sudo perf stat -e 'power/energy-pkg/' -e 'power/energy-cores/' ./primes_naive 300000 — замір енергії програми.

Крок 4: Порівняння з оптимізованою версією

  • g++ -O3 -g -march=native primes_optimized.cpp -o primes_avx — компіляція з AVX2;
  • ./primes_avx 300000 — замір часу (швидкий тест);
  • sudo perf stat -d ./primes_avx 10000000 — статистика під навантаженням;
  • sudo perf stat -e 'power/energy-pkg/' -e 'power/energy-cores/' ./primes_avx 10000000 — енергія під навантаженням;
  • sudo perf record -F 99 -g ./primes_avx 10000000 — профіль для FlameGraph.
